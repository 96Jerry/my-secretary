# CGV 예매 조회 API

공개 문서가 없어 예매 페이지의 네트워크 요청을 보고 정리한 내용이다.
`cgv.co.kr/api/v1/*`는 CGV 프런트엔드(Next.js)가 쓰는 BFF로, 비로그인 공개 조회를
그대로 허용한다. 백엔드(`api.cgv.co.kr/cnm/atkt/*`)는 Bearer 토큰을 요구한다.

## 공통

- 회사코드 `coCd=A420`은 모든 요청에 필수. 빠지면 400 `회사코드는 필수 값입니다`.
- 응답 봉투: `{ "statusCode": 0, "statusMessage": "조회 되었습니다.", "data": [...] }`
  - `statusCode`가 `0`이 아니면 실패다.
- cgv.co.kr은 Cloudflare 뒤에 있다. User-Agent가 없으면 403 + HTML 에러 페이지가
  온다. 차단 시에도 상태코드만 보고 `res.json()`을 부르면 `Unexpected token '<'`가
  나므로 `content-type`을 먼저 확인해야 한다.
- HTTP/2라 `statusText`가 항상 빈 문자열이다. 로그에 찍을 때 상태코드만 쓴다.

## 엔드포인트

### 1. 극장+영화 예매 가능 상영일자

```
GET /api/v1/booking/searchSiteScnscYmdListByMov?coCd=A420&siteNo=0013&movNo=30001323
→ [{ "scnYmd": "20260916", "hldyYn": null }, ...]
```

**이 프로젝트가 예매 오픈 감지에 쓰는 엔드포인트.** 오늘부터 약 7일치가 오고
과거 날짜는 섞이지 않는다. 예매가 아직 열리지 않았으면 빈 배열이다.
따라서 목록에 날짜가 새로 생기는 것 자체가 그 영화의 예매 오픈 신호다.

### 2. 극장+날짜+영화 상영회차

```
GET /api/v1/booking/searchSchByMov
      ?coCd=A420&siteNo=0013&scnYmd=20260917&movNo=30001323&rtctlScopCd=08
```

`rtctlScopCd`는 조회범위 코드. 영화 우선 예매 화면은 `08`을 보낸다.

### 3. 영화 단위 상영일자 (전국)

```
GET /api/v1/content/cgvct/searchMovScnYmdList?coCd=A420&movNo=30001323
```

극장 구분이 없고 **과거 날짜까지 포함**한다. 이 프로젝트에서는 쓰지 않는다.

## 회차 응답 주요 필드

| 필드 | 의미 | 비고 |
| --- | --- | --- |
| `siteNo` / `siteNm` | 극장 번호 / 이름 | **요청한 극장과 다를 수 있다** (아래 참고) |
| `scnsNo` / `scnsNm` | 상영관 번호 / 이름 | 번호는 극장 안에서만 유일 |
| `scnYmd` | 상영일 `YYYYMMDD` | |
| `scnsrtTm` / `scnendTm` | 시작 / 종료 시각 `HHmm` | `2500` = 익일 01:00 |
| `scnSseq` | 그 상영관의 당일 회차 순번 | 앞 회차가 추가되면 전부 밀린다 |
| `movNo` / `movNm` | 영화 번호 / 제목 | 제목에 상영 포맷 없음 |
| `expoProdNm` | 노출용 상품명 | `오디세이(IMAX LASER 2D)` |
| `movkndDsplNm` | 상영 포맷 | `2D`, `4DX 2D`, `IMAX LASER 2D` |

| `rlMovStartTm` | 광고 후 실제 시작 시각 | |
| `salEndTm` | 판매 마감 시각 | |

## 함정

### siteNo는 극장이 아니라 건물 묶음이다

`siteNo=0013`(용산아이파크몰)으로 요청해도 응답에 `siteNo=P013`(씨네드쉐프 용산)
회차가 섞여 온다. 같은 아이파크몰 건물에 있는 별개 지점이라 예매 화면이 함께
보여주기 때문이다. 결과에서 `siteNo`를 다시 걸러야 한다.

`scnsNo`는 극장 안에서만 유일하므로, 회차를 식별하는 키에 극장번호가 빠지면
서로 다른 극장의 같은 번호 상영관이 같은 키를 만든다.

### scnSseq는 식별자가 아니다

당일 순번이라 앞 시간대에 회차가 하나 추가되면 뒤 번호가 전부 밀린다.
중복 판단용 키에 넣으면 기존 회차가 통째로 신규로 오탐된다.
좌석 수도 계속 변하므로 마찬가지다.

안정적인 조합: `극장번호 : 상영일 : 상영관번호 : 시작시각 : 영화번호`

### 심야 상영은 24시를 넘긴다

`scnsrtTm: "2500"`, `scnendTm: "2802"`처럼 온다. `Date`로 파싱하면 깨진다.

### 극장 전용 상영일자 목록에는 과거가 섞인다

`searchSiteScnscYmdListBySite`(극장 단위)와 위 3번(영화 단위)은 과거 날짜를
포함한다. "가까운 날짜부터"라고 정렬하면 과거를 먼저 보게 된다.
1번(극장+영화)만 오늘 이후로 정리되어 온다.

## 요청 빈도

짧은 시간의 연속 요청에 민감하다. 수 분 안에 10여 건이면 403이 떨어진다.
일일 총량보다 버스트가 문제로 보인다.

### 403은 레이트 리밋이 아니다

10분에 2건(시간당 12건) 수준에서도 403이 섞인다. 응답 본문은 Cloudflare 기본
에러 페이지가 아니라 CGV가 만든 차단 페이지이고, 내용은 아래와 같다.

```
비정상적으로 CGV에 접속한 것이 확인되어 이용이 제한되었어요.
자세한 내용은 고객센터(1544-1122)로 문의해 주세요.
RAY_ID / CLIENT_IP
```

`error code: 1015`도 `retry-after`도 `cf-mitigated`도 없다. 즉 요청량 초과가
아니라 자동 접속 탐지다. HTTP 버전과도 무관하다 — HTTP/2(curl)와
HTTP/1.1(Node fetch) 양쪽에서 같은 페이지가 나왔다.

다만 지속 차단은 아니다. 403이 난 다음 주기의 요청은 정상 통과한다.
요청 단위로 가끔 걸러지는 형태이며, 실패한 주기는 다음 주기가 재시도하므로
최대 손실은 한 주기 분량의 지연이다.

UA를 브라우저로 바꾸거나 프록시를 경유하면 통과할 여지가 있으나, 위 문구를
확인한 뒤에 그렇게 하는 것은 명시적 접근 제한의 우회에 해당하므로 하지 않는다.
